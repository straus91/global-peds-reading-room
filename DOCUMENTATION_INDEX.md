## 🎯 Documentation Best Practices

### When to Update Documentation

**Always update docs when you**:
- Add a new feature
- Change database models
- Modify API endpoints
- Update deployment procedures
- Discover new best practices
- Fix a tricky bug (add to troubleshooting)

**Which docs to update**:
- [docs/PROJECT_MAP.md](docs/PROJECT_MAP.md) - For new files, models, API endpoints
- [docs/CHANGELOG.md](docs/CHANGELOG.md) - For all changes
- [docs/AI_GUIDE.md](docs/AI_GUIDE.md) - For AI system changes
- [docs/QUICK_REFERENCE.md](docs/QUICK_REFERENCE.md) - For new common commands
- [README.md](README.md) - For major feature additions

### Documentation Quality Guidelines

✅ **Good Documentation**:
- Clear, concise language
- Real examples with actual code/commands
- Step-by-step procedures
- Troubleshooting sections
- "When to use this" guidance
- Links to related docs

❌ **Avoid**:
- Vague descriptions
- Outdated information
- Missing prerequisites
- No examples
- Broken links

### Still Stuck?

1. Search all markdown files:
   ```bash
   grep -r "your search term" docs/ .claude/docs/ *.md
   ```

2. Check the archive (might have historical info):
   ```bash
   grep -r "your search term" docs/archive/
   ```

3. Create an issue documenting what you couldn't find - helps improve docs!
